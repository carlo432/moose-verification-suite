How to read the ledgerTolerance first, result second

A verification result only means something if the test could have failed. Three conventions here exist to keep that true, and one of them is a caution about this page's own numbers.

Declared before solving

Each tolerance was committed to the repository before the case ran. None was widened afterwards to accommodate a result.

The rail is logarithmic

Full width is the declared tolerance. The mark shows where the measured error landed, on a decade scale from 10−8 to 1 — margins span eight orders of magnitude, so a linear bar would hide almost all of them.

Error is not always a subtraction

Where the scored metric is a profile norm, the number is a whole-field comparison, not the difference between two headline values. The metric is named on every row.

Amber means close

Four cases used more than half their budget. They passed, but they are the ones to interrogate first — see the recorded caveats below.

Recorded against these resultsThree things a reader should know

These are properties of the results, not of the reporting, so they are recorded rather than corrected. An audit of all 24 cases found no verdict that needed changing; it did find these.

T2-14 · 87% of budget

Natural convection has not plateaued

The Ra = 10⁶ sequence runs 16.11 → 6.47 → 4.32 → 3.49% across four meshes. Monotone and heading the right way, but that is roughly first-order convergence, so 3.49% is the error at 128² and not a converged value.

T2-13 · post hoc selection

The cavity's scoring rule changed

The original rule scored the finest mesh and returned 0.1475 — a fail. The current rule scores the most time-converged run. Ghia is a steady reference, so that is physically right, but the tolerance was met by changing what is measured, and the 128² run remains unconverged.

T2-20 · rate beats the method

Fourth order from a second-order scheme

Errors fall by 16× per mesh doubling where 4× is expected. That points to a manufactured source nearly representable in the element space, so this case verifies the source-to-conduction path rather than the solver's spatial accuracy.

ScopeWhat this does not claim

No experimental validation

Every case is [A] closed form or [B] published benchmark. There are no [E] rows. Two cases were reclassified down to [A] rather than let them claim experimental backing they did not have.

The coupled case is in

The Turek & Hron FSI1 fluid–structure benchmark now passes at 0.68% on tip displacement, with drag corroborating independently at 0.12%. Its two halves were validated separately on the same mesh before coupling.

Two dimensions, single physics per case

These are capability checks, not qualification of a coupled production model. Each isolates one solver path so a failure localises instead of being guessed at.

MethodRules the suite holds itself to

  • Tolerances are declared before the solve, in version control, and are never widened to convert a fail into a pass.
  • No unsourced reference numbers. Every anchor is a derivation or a citation. Where no sourced value existed, the case was reclassified rather than allowed to imply one.
  • A test whose measurement cannot fail is not evidence. Checks placed where a boundary condition pins the answer, or where symmetry fixes it exactly, are treated as bugs — one was found and rebuilt during the audit.
  • An error that does not move under refinement is a wrong reference or a wrong model form, never discretization.
  • Prefer invariants and volume integrals to differentiated fields, hand-rolled normals and point probes.
